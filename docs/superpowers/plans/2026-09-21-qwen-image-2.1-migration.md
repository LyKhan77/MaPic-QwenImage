# Migrasi MaPic: GLM-Image → Qwen-Image 2.1

> **For agentic workers:** REQUIRED SUB-SKILL: Gunakan `superpowers:subagent-driven-development` (disarankan) atau `superpowers:executing-plans` untuk mengeksekusi plan ini task-per-task. Langkah memakai checkbox (`- [ ]`).

**Goal:** Mengganti mesin inference MaPic dari `zai-org/GLM-Image` (9B AR + 7B decoder) ke `Qwen/Qwen-Image-2.1` (7B single-stream DiT + Qwen3-VL 8B), rename penuh ke `qwen_image_server`, menambahkan kontrol **True CFG Scale + Negative Prompt**, serta **selector resolusi 1K/2K** — lalu deploy dan uji di server `gspe-ai2` (192.168.2.142).

**Architecture:** 3 service tetap: Frontend React (:5151) → Backend FastAPI (:8181) → Inference Server (:30000). Yang berubah hanya isi inference server (pipeline Qwen), kontrak request backend→server, dan kontrol UI. Supabase Auth/DB/Storage, Cloudflare Tunnel, dan Vercel tidak berubah strukturnya.

**Tech Stack:** PyTorch (cu128) · transformers ≥ 5.17 (Qwen3VL) · diffusers (git main, wajib — `QwenImage21Pipeline` belum ada di rilis stabil) · accelerate · FastAPI/Uvicorn · React + Vite + TanStack Query.

---

## Keputusan yang sudah divalidasi (2026-09-21)

1. **Rename penuh** ke `qwen_image_server`, env `GLM_IMAGE_API_URL` → `QWEN_IMAGE_API_URL`, error class `GlmImageError` → `QwenImageError`.
2. **CFG**: slider Guidance diganti **True CFG Scale** (1.0 = off) + field **Negative Prompt** baru. CFG hanya dikirim aktif bila `true_cfg_scale > 1` DAN `negative_prompt` terisi.
3. **Resolusi**: dibuat konfigurasi — selector 1K/2K di UI + default via env (`QWEN_DEFAULT_RESOLUTION`).
4. **Hardware**: user akan cek manual di server dan mengirim hasilnya. Fase 0 memakai perintah inventaris; nilai `MAX_MEMORY`/`device_map` dipilih setelah data masuk.

## Kontrak yang berubah (referensi cepat)

| Aspek | Sebelum (GLM-Image) | Sesudah (Qwen-Image 2.1) |
|---|---|---|
| Pipeline | `GlmImagePipeline` | `QwenImage21Pipeline` (`diffusers.pipelines.qwenimage21`) |
| Model ID | `zai-org/GLM-Image` | `Qwen/Qwen-Image-2.1` |
| Guidance | `guidance_scale` (1.0–5.0, default 1.5) | `true_cfg_scale` (default 1.0 = off) + `negative_prompt` |
| Stage | `warmup → encoding → ar_sampling → diffusion → decoding` | `warmup → encoding → diffusion → decoding` |
| AR config | `pipe.vision_language_encoder.generation_config.*` | tidak ada (hapus) |
| Snapping ukuran | `ceil(w/32)*32` | `floor(w/32)*32` (pipeline: `width // 32 * 32`) |
| Resolusi | 1024x1024 | 1024/2048, native 2K; `output_resolution` diisi = resolution |
| Gambar referensi | maks 3, di-`resize` paksa ke `(W,H)` | maks 10, **jangan** di-resize (pipeline yang atur bucket aspect ratio) |
| Steps default | 50 T2I / 35 I2I | 40 |
| Output | RGB PNG | bisa RGBA PNG (PNG aman, UI tidak perlu diubah) |
| Dependensi | transformers git, diffusers git | **transformers ≥ 5.17**, diffusers git main (pin commit) |

```python
"""Uji kelayakan Qwen-Image-2.1: VRAM puncak, timing, RGBA, multi-referensi.

Jalankan: python smoke_test.py --resolution 1024
"""

import argparse
import time

import torch
from diffusers import QwenImage21Pipeline
from PIL import Image


def vram_report(tag: str):
    for i in range(torch.cuda.device_count()):
        peak = torch.cuda.max_memory_allocated(i) / 1024**3
        total = torch.cuda.get_device_properties(i).total_memory / 1024**3
        print(f"[{tag}] GPU {i}: peak {peak:.2f} GB / total {total:.2f} GB")


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--resolution", type=int, default=1024)
    parser.add_argument("--steps", type=int, default=40)
    parser.add_argument("--model", default="Qwen/Qwen-Image-2.1")
    parser.add_argument("--refs", type=int, default=0)
    args = parser.parse_args()

    print(f"Loading {args.model} (bf16, device_map=balanced)...")
    t0 = time.time()
    pipe = QwenImage21Pipeline.from_pretrained(
        args.model,
        torch_dtype=torch.bfloat16,
        device_map="balanced",
    )
    print(f"Load: {time.time() - t0:.1f}s")
    if hasattr(pipe.vae, "enable_tiling"):
        pipe.vae.enable_tiling()
    if hasattr(pipe.vae, "enable_slicing"):
        pipe.vae.enable_slicing()
    vram_report("after_load")

    refs = None
    if args.refs:
        refs = [Image.new("RGB", (1024, 1024), (200, 180, 160)) for _ in range(args.refs)]

    torch.cuda.reset_peak_memory_stats()
    t0 = time.time()
    out = pipe(
        prompt="A ceramic teapot on a wooden table, morning light",
        image=refs,
        width=args.resolution,
        height=args.resolution,
        output_resolution=args.resolution,
        num_inference_steps=args.steps,
    ).images[0]
    elapsed = time.time() - t0
    print(f"Generate {args.resolution}px steps={args.steps} refs={args.refs}: {elapsed:.1f}s")
    vram_report("after_generate")

    out.save("smoke_out.png")
    print("Saved smoke_out.png mode=", out.mode)
    Image.new("RGB", (64, 64)).save("smoke_rgb_control.png")


if __name__ == "__main__":
    main()
```

```python
def _snap_to_32(size: str) -> tuple[int, int]:
    parts = size.lower().split("x")
    w, h = int(parts[0]), int(parts[1])
    multiple_of = 32
    return (max(multiple_of, w // multiple_of * multiple_of),
            max(multiple_of, h // multiple_of * multiple_of))
```

### Task 3.4: Kalibrasi ulang estimasi waktu

**Files:** Modify: `frontend/src/lib/generation.ts`

**Prasyarat:** tabel angka dari Task 0.5 sudah terisi.

- [ ] **Step 1: Tulis ulang fungsi dengan angka nyata**

Contoh struktur (konstanta **wajib** diganti dengan hasil Task 0.5):

```typescript
const BASE_SECONDS = 8          // overhead di luar denoising (dari pengukuran)
const SECONDS_PER_STEP_1K = 1.2 // dari pengukuran 1K / 40 steps
const REF_SECONDS = 3           // biaya encoding per gambar referensi
const CFG_MULTIPLIER = 1.9      // true_cfg_scale > 1 = dua forward pass per step

export function estimateTotalSeconds(
  steps: number,
  numRefImages: number,
  resolution: number = 2048,
  cfgEnabled: boolean = false,
): number {
  const scaleFactor = resolution >= 2048 ? 3.5 : 1
  const base = BASE_SECONDS + steps * SECONDS_PER_STEP_1K * scaleFactor
  const refOverhead = numRefImages > 0 ? 5 + numRefImages * REF_SECONDS : 0
  const cfgFactor = cfgEnabled ? CFG_MULTIPLIER : 1
  return Math.round((base + refOverhead) * cfgFactor)
}
```

Cara menurunkan konstanta dari hasil pengukuran:

- `BASE_SECONDS` ≈ `Generate(1K, 40 steps, 0 ref)` − `40 × SECONDS_PER_STEP_1K`
- `SECONDS_PER_STEP_1K` = `Generate(1K, 40 steps, 0 ref)` / 40
- `scaleFactor` = `Generate(2K, 40 steps, 0 ref)` / `Generate(1K, 40 steps, 0 ref)`
- `REF_SECONDS` = (`Generate(2K, 40, 3 ref)` − `Generate(2K, 40, 0 ref)` − 5) / 3

## Lampiran A — Rollback

Jika migrasi gagal di tengah jalan:

1. **Kode:** `git revert <commit-range>` atau `git checkout <commit-terakhir-glm>` lalu deploy ulang. Karena rename folder terjadi di Task 1.1, revert harus mencakup commit itu.
2. **Server:** `sudo systemctl disable --now qwen-image && sudo systemctl enable --now mapic-glm`, lalu kembalikan `.env` ke `GLM_IMAGE_API_URL`.
3. **Data:** tidak ada migrasi skema Supabase, jadi tidak ada data yang perlu dipulihkan.
4. **Jangan hapus** bobot `zai-org/GLM-Image` di cache HF sampai Task 5.1 lulus penuh.

## Lampiran B — Catatan versi & risiko terbuka

- **diffusers dari git main** dapat berubah tanpa peringatan. Setelah Fase 0 lulus, pin commit-nya di `requirements.txt`, contoh: `git+https://github.com/huggingface/diffusers.git@<sha>`.
- **transformers 5.x** adalah lompatan mayor. Pipeline QwenImage21 sendiri memasang forward hook untuk menetralkan perilaku `hidden_states[-1]` di transformers 5.0, dan menyebut TODO untuk `tie_last_hidden_states=False` di transformers 5.18. Jangan upgrade transformers tanpa menjalankan ulang Task 1.7 Step 3.
- **Optimisasi opsional (jangan dikerjakan sebelum acceptance lulus)**: mengganti attention processor ke `QwenImage21FlexAttnProcessor` + `pipe.transformer.compile()` (butuh `flex_attention`, torch ≥ 2.5) untuk mempercepat prefill block-causal. Wajib compile sebelum dipakai, dan **mengubah output secara bit**.
- **8-bit quantization** via `PipelineQuantizationConfig` belum divalidasi untuk QwenImage21Pipeline. Jadikan opsi cadangan bila mode B/C terlalu lambat, bukan jalur utama.
- **Angka VRAM/timing di plan ini adalah placeholder** sampai Task 0.4 & 0.5 selesai. Jangan mengisi `MAX_MEMORY` berdasarkan tebakan dari konfigurasi GLM lama (56 GB tri-GPU) — server target belum diketahui spesifikasinya.
